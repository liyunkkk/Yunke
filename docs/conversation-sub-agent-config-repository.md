# Conversation sub-agent configuration repository (scope D)

`ConversationSubAgentPreferences` is an **internal, explicit-owner** store, not an active-conversation singleton. Supply `SharedPreferences` (or initialize `Prefs.localAgentPreferences()` first) and optionally `canEdit(owner)`; return false only while that owner's **parent** agent is running. Background child work need not reject edits. Only `update` invokes this write guard: lifecycle callers must gate their own create/bind/delete/import actions. UI and runtime wiring are outside this module.

- `SubAgentConfigKey.Conversation(id)` and `Draft(token)` are distinct. `createDraft(sourceOwner)` issues an independent token and copies all settings. `createConversation(newOwner, previousOwner)` copies the preceding conversation once; an existing destination always wins. Do not use null as a shared draft identity.
- `snapshot(owner)` and `flow(owner)` read the same owner's immutable-by-convention, detached configuration. `update(owner) { old -> old.copy(...) }` atomically commits and returns `Saved(revision, detachedConfig)` or `Rejected`. Revision is per repository instance; listeners must call `refreshAfterRestore()` after external restore. Capture `snapshot(owner)` at job start; do not dynamically read the current UI owner from a running job.
- `bindDraft(draft, conversation)` commits the conversation without deleting the draft; repeated binds preserve the existing conversation (including edits since the initial bind). Only after conversation persistence succeeds call `confirmBoundDraft`; an absent conversation prevents cleanup. `delete(owner)` is explicit.
- `ConversationSubAgentConfig` includes enabled, full `SubAgentProfile` list (including disabled items, model, reasoning memory, resolution, tier), per `(providerId, API model name)` parallel limits (`0` means unlimited), and diagnosticsEnabled. `poolKey(owner, model)` namespaces future pool leases by owner. This store never calls `SubAgentModelPools.configure`; UI changes in A cannot resize B's pool through this module. Resolving selection IDs to API model names belongs to the integration layer.
- `export(owner)` yields one versioned owner payload; `importOwner(target, archive, overwrite=false)` explicitly remaps the payload to `target` (whether draft or conversation). Keep-existing by default, replace only with `overwrite=true`; other owners are untouched. This is a per-owner archive **format/API**, not a backup integration. Backup should export/match conversation IDs, decide how to handle drafts and old archives, validate restores with `validateRestoredPreferences()`, then invoke `refreshAfterRestore()`. Malformed payloads throw; no automatic reset.
- The first read of a missing owner freezes one seed from the old global `agent_child_profiles_v1` or legacy four slots (and old model limit keys for selected models), without modifying old settings. The old `agent_collaboration_<conversationId>` switch applies to that conversation's first materialization; an existing new-format owner is never overwritten. An explicitly empty old profile array remains empty. Invalid JSON fails rather than masquerading as missing. The seed is written once and stays fixed despite subsequent global changes. Explicit copies override legacy per-target defaults.

Caveats: repository instance synchronization protects its own commits; use a single shared instance per preference store or external cross-instance synchronization. SharedPreferences offers synchronous per-key commits, not atomic multi-key backups. The optional guard applies to `update` only, not lifecycle/restore. Runtime, coordinator, UI and backup wiring are intentionally not implemented here.
