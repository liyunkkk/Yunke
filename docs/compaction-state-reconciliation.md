# 压缩状态与时间线校对

## 修复目的

避免将历史计划重新标为当前待办，或将不同时点的提交/构建/下载/未提交编辑混为同一状态。压缩阈值、工具批次边界、尾部保留和原文归档策略不变。

## 行为

- 源分块携带选中前缀的消息范围与分块顺序；中间摘要逐层标明顺序。新增说明与证据参与真实请求预算计算，不额外启动普遍性的校对模型请求。
- 合并使用状态对账规则：同任务/仓库/run/commit/artifact 的较晚已验证结果覆盖较早计划，不同身份不可相互覆盖。历史 clean/committed 与后续 dirty 是不同阶段；构建成功不证明已下载、安装，或后续编辑已包含在构建里。
- 最新真实用户请求优先于中间摘要里的“最终指令”。摘要只描述选中前缀的终点，未压缩尾部始终优先。
- `AgentCompactionEvidence` 从原文独立提取严格绑定 tool_call_id 的 `gh run view <id>` JSON 状态，用消息位置与仓库/run ID 标记。仅白名单字段进入合并，不复制 shell 命令、任意 stdout 或凭据。命令串、失败、截断、返回 ID 不一致等不升级为状态凭据。
- 独立证据进入现有 merge，并将最新观察附到最终摘要的 Critical Context。即使中间摘要遗漏状态，已识别的 run 结果仍能保留。若 Pending Jobs / Next Step 明确将同 ID 的已结束 run 写回等待完成，则拒绝摘要、保留原文，不重复付费修摘要。
- 状态凭据最多 64 条、12,000 字符，超界拒绝本次压缩而非静默丢弃末尾状态。近期短用户消息只用作意图提示，明确标为部分覆盖，不是完成凭据。
- 8 个必需章节必须齐全、有内容（允许显式 `(none)`）、顺序正确且不重复；未知同级标题拒绝。支持已有中英文别名、外层 Markdown fence 和内部代码块。缺失章节不再自动补 `(none)`。
- 格式修复使用完整候选文本，取消 `take(12000)`；复用请求预算检查，无法容纳则保留原文。
- 多层合并的收缩判断仅比较摘要正文，不把新增顺序标签的消失当成有效压缩。

## 范围与限制

这不是通用事实证明器。独立机器证据与冲突拦截目前针对严格识别的 GitHub 工作流状态；任意自然语言、任意命令组合、下载/安装/工作区 clean/dirty 的语义仍依赖原文分块及合并模型校对，不声称已全面自动验证。有歧义时保留不确定性，不猜测已完成/未完成。

不会修改既有会话摘要或替用户重跑原来的编译、下载等操作。需构建并更新应用后才能对新压缩生效。

## 验证

新增/扩展测试覆盖：中间摘要遗漏成功但合并仍收到独立证据、同 ID running→success / success→rerun、不同仓库隔离、错误 ID/失败 shell/通用 ok 不升级为凭据、旧待办拒绝且尾部不变、否定语句边界、证据上限、章节缺失/乱序/重复/代码块、完整格式修复与超预算拒绝。

本地无 Android SDK 时，使用临时 JVM harness 编译实际压缩器/预算/分块/证据/格式类，通过 mock provider 测试；只替身化 Android/配置/网络工厂外围依赖。该验证不等同于 Android 全量 Gradle 测试，也未调用真实付费模型。
